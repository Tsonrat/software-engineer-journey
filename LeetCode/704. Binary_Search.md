# 0704. Binary Search

## Description

Given an array of integers `nums` which is sorted in ascending order, and an integer `target`, return the index of `target` if it exists.

If `target` does not exist, return `-1`.

You may assume that all elements in `nums` are unique.

---

## Example

### Example 1

**Input**

```text
nums = [-1,0,3,5,9,12]
target = 9
```

**Output**

```text
4
```

---

### Example 2

**Input**

```text
nums = [-1,0,3,5,9,12]
target = 2
```

**Output**

```text
-1
```

---

# 💻 My Solution

## Solution 1 - Binary Search

```java
class Solution {
    public int search(int[] nums, int target) {

        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {

            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        return -1;
    }
}
```

---

# 🧠 My Notes

## Binary Search

Because the array is already sorted, Binary Search can eliminate half of the remaining search space on every iteration.

Instead of checking every element one by one, compare the middle element with the target.

* If `nums[mid] == target`, return `mid`.
* If `nums[mid] < target`, search the right half.
* If `nums[mid] > target`, search the left half.

---

## Why `while (left <= right)`?

When `left == right`, there is still one element left to check.

For example:

```text
left = 3
right = 3
```

The element at index `3` has not been compared yet.

Only when:

```text
left > right
```

does it mean the search space is empty.

---

## Why `mid = left + (right - left) / 2`?

This calculates the middle position of the current search range.

Compared with:

```java
(left + right) / 2
```

this version avoids potential integer overflow when `left` and `right` are very large.

---

## Why `mid + 1` and `mid - 1`?

Once `nums[mid]` has been compared, we already know it is **not** the target (unless it has already been returned).

Therefore, we must exclude `mid` from the next search range.

```java
left = mid + 1;
right = mid - 1;
```

If we write:

```java
left = mid;
```

or

```java
right = mid;
```

the search range may never shrink, causing an infinite loop.

| Complexity | Value        |
| ---------- | ------------ |
| Time       | **O(log n)** |
| Space      | **O(1)**     |
